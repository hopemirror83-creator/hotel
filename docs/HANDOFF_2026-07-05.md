# 호텔로그 작업 인수인계 기록

작성일: 2026-07-05

## 프로젝트 개요

호텔로그(HotelLog)는 기존 여행/호텔 후기형 사이트를 기반으로 만든 호텔 후기 분석 사이트입니다.

목표는 아고다 예약 사이트를 복제하는 것이 아니라, 사용자가 예약 전에 “이 호텔이 나에게 맞는지” 빠르게 판단할 수 있도록 돕는 후기 분석형 콘텐츠 사이트입니다.

현재 배포 도메인:

- 실제 도메인: `https://hotel.product-pack.com`
- Cloudflare Pages 프로젝트: `hotellog`
- 개발/작업 폴더: `C:\Users\USER\OneDrive\문서\테스트\hotellog`

## 핵심 원칙

1. 아고다 후기 원문은 사이트에 노출하지 않습니다.
2. 후기 원문은 DB에 장기 저장하지 않습니다.
3. 저장/노출되는 것은 AI가 생성한 요약, 장점, 단점, 추천대상, 주의사항, 체크포인트, FAQ입니다.
4. 아고다 API 데이터를 그대로 복붙한 페이지가 아니라, 예약 전 판단을 돕는 후기 분석 페이지가 되어야 합니다.
5. 본문은 광고성 문구보다 장점과 단점을 함께 보여주는 신뢰형 문체를 유지합니다.

## 사용 데이터와 API

기존 작업 방식은 계속 유지합니다.

- 아고다 호텔 리스트 파일: `56A3C1A2-0531-49F3-8720-D7D4B1410E41_KO.csv`
- 아고다 Affiliate API: 호텔 기본 정보, 가격, 평점, 리뷰 수, 제휴 링크, 이미지 확인
- 네이버 검색 API: 호텔명 기반 블로그/웹문서 검색 결과 수집
- 네이버 지도 API: 주소, 좌표, 지도 표시
- Gemini API: 호텔별 후기형 콘텐츠 생성

환경변수 이름:

- `AGODA_AFFILIATE_KEY`
- `NAVER_CLIENT_ID`
- `NAVER_CLIENT_SECRET`
- `PUBLIC_NAVER_MAP_CLIENT_ID`
- `GEMINI_API_KEY`

API 키 원문은 보안상 이 문서에 쓰지 않습니다. 기존 대화 또는 로컬 환경 설정을 확인하세요.

## 기존 개별 호텔 페이지 구성

개별 호텔 상세 페이지는 아래 흐름을 유지합니다.

1. 호텔명/지역/주소/대표 이미지
2. 아고다 평점
3. 후기 개수
4. 예상 1박 가격
5. 아고다 예약 확인 버튼
6. 후기 요약
7. 많이 언급된 장점
8. 반복적으로 언급된 단점
9. 추천 여행자 유형
10. 비추천/주의 여행자 유형
11. 예약 전 체크포인트
12. 네이버 지도
13. 후기형 블로그 본문
14. 예약 전 FAQ
15. 네이버 블로그 후기 참고 링크
16. 관련 지역 가이드 링크
17. 하단 아고다 예약 확인 버튼

후기형 블로그 본문 소목차는 기존 방식 유지:

- 이 호텔 선택 이유
- 호텔 구성 및 특징
- 주요 장점
- 경쟁 제품과 비교
- 팁 & 고려사항
- 이런 분들 추천해요

모바일 가독성을 위해 문단은 짧게 유지합니다.

## 최근 추가된 핵심 요구사항 1: 검색의도 기반 제목/FAQ

새로 추가된 핵심 방향입니다.

호텔 페이지를 만들거나 기존 페이지를 보강할 때:

1. 호텔명을 네이버 검색
2. 호텔명을 구글 검색
3. 자동완성/연관 검색 신호 확인
4. 자주 묻는 질문 유형 추출
5. 검색의도를 분류
6. 제목, 소제목, FAQ, 추천대상, 비추천대상, 본문 순서에 반영

검색의도 분류 예:

- 예약
- 교통
- 체크인
- 주차
- 조식
- 객실
- 가족
- 커플
- 오션뷰
- 공항 접근
- 가성비

현재 적용 방식:

- `src/pages/hotel/[slug].astro`에서 `searchIntent`를 읽습니다.
- `searchIntent`가 있으면 개별 페이지 `<h1>`, SEO title, meta description, 추천/비추천 대상, FAQ가 검색의도형으로 바뀝니다.
- 지역별 파일에서 호텔 주소/본문/호텔명 기반으로 지역 키워드를 추정합니다.

예:

- 영종도: `파라다이스 시티 영종도 가족 호캉스·수영장·체크인 후기 모음`
- 부산: `코오롱 씨클라우드 호텔 해운대 부산 후기 모음`
- 강원: `이팝리조트 A동 춘천 강원 후기 모음`

중요:

- 예전에는 인천/영종도 기준 문구가 다른 지역 본문에 남는 문제가 있었습니다.
- 2026-07-05에 `src/pages/hotel/[slug].astro`에서 비인천 페이지의 `영종도`, `인천공항`, `공항권`, `공항 환승용` 관련 비교 문구를 지역 기준 문장으로 바꾸도록 보정했습니다.
- 앞으로 새 지역을 만들 때도 “인천공항/영종도” 문구가 다른 지역에 섞이지 않는지 꼭 확인해야 합니다.

## 최근 추가된 핵심 요구사항 2: 지역별 묶음/비교 페이지

영종도에서 테스트한 의사결정 지원형 페이지를 다른 지역으로 확장하는 전략입니다.

단순 호텔 목록이 아니라, 검색 유입을 노리는 지역/목적별 묶음 페이지를 만듭니다.

예:

- 서울 강남 호텔 후기
- 서울 명동 호텔 후기
- 서울 홍대/마포 호텔 후기
- 서울 동대문 호텔 후기
- 부산 해운대 호텔 후기
- 부산 서면 호텔 후기
- 제주공항 근처 호텔 후기
- 서귀포 호텔 후기
- 인천 송도 호텔 후기
- 강화 호텔 후기
- 경기 수원 호텔 후기

묶음 페이지는 아래 구성을 따릅니다.

1. 지역명
2. 페이지 목적
3. 후기 분석 기준
4. 마지막 업데이트 날짜
5. 분석 호텔 수
6. 추천 TOP 리스트
7. 호텔별 추천 이유 3개
8. 주의할 점 1개
9. 관련 태그
10. 개별 호텔 후기 링크
11. 비교표

관련 데이터 파일:

## 메인 페이지 최근 상태

메인 페이지에서 수정된 것:

1. “지역별 호텔 찾기”는 기본 닫힌 상태로 변경했습니다.
2. “인기 호텔 후기”는 지역별로 접히는 구조로 변경했습니다.
3. 상단 메뉴는 서울, 부산, 제주, 인천, 강원 등 주요 지역 앵커로 이동합니다.
4. 관리자/수집 상태 버튼은 방문자에게 노출되지 않도록 이전에 정리했습니다.

- 이 호텔 선택 이유: 호텔 전체/외관
- 호텔 구성 및 특징: 객실
- 주요 장점: 시설
- 경쟁 제품과 비교: 시설/로비
- 팁 & 고려사항: 주변/위치
- 이런 분들 추천해요: 호텔 대표 이미지

## 다음 작업자가 꼭 알아야 할 주의점

1. 새 지역 확장 시 기존 인천/영종도/공항권 문구가 본문에 섞이지 않는지 먼저 확인해야 합니다.
2. 검색의도형 제목과 FAQ는 지역별 `*SearchIntents.ts` 파일에 추가하는 방식이 안정적입니다.

4. 아고다 API/파일 기반 데이터 수집, 네이버 검색/지도, Gemini 생성 방식은 기존 유지입니다.
5. 원문 후기 노출 금지 원칙은 계속 유지해야 합니다.
6. 새로 대량 생성한 뒤에는 반드시 `check`, `build`, 샘플 HTML 확인, 배포 순서로 진행합니다.
