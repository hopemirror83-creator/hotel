# 호텔로그 사이트 설계

## 목표

호텔로그는 예약 사이트를 복제하지 않고, 예약 전 판단을 돕는 호텔 후기 분석 사이트로 만든다. 아고다 기본 정보, 네이버 검색 신호, 네이버 지도 위치 정보를 결합해 호텔마다 장점, 단점, 추천 여행자, 주의 여행자, 체크포인트를 정리한다.

## 시작 범위

- 사이트명: 호텔로그 (HotelLog)
- 개발 주소: `hotel.hopemirror83.workers.dev`
- 표시 도메인: `hotel.product-pack.com`
- 시작 지역: 인천 영종도
- 시작 호텔 수: 5개
- 배포: Cloudflare Pages
- 데이터베이스: Cloudflare D1 `hotellog`

## 콘텐츠 원칙

- 아고다 후기 원문은 사이트에 노출하지 않는다.
- 후기 원문을 D1에 장기 저장하지 않는다.
- 저장 대상은 AI가 생성한 요약, 장점, 단점, 추천 대상, 주의 대상, 체크포인트로 제한한다.
- API 데이터를 그대로 붙여 만든 페이지가 아니라 예약 전 의사결정 페이지로 구성한다.
- 원문 후기와 유사한 문장이 감지되거나 내용이 일반적이면 발행하지 않는다.

## 주요 페이지

- `/`: 영종도 호텔 분석 목록과 서비스 소개
- `/hotel/[slug]/`: 호텔별 예약 전 확인 페이지
- `/admin/`: 운영자용 수집/생성/검토 화면 초안

## 관리자 흐름

1. 호텔 데이터 수집
2. 네이버 검색/지도 신호 수집
3. Gemini JSON 콘텐츠 생성
4. 품질 검사
5. 생성 결과 미리보기
6. 수동 수정 후 발행
7. 발행/비공개 상태 관리

## 품질 기준

- 호텔명, 위치, 장단점, 체크포인트 중 최소 3개 이상이 호텔 고유 정보여야 한다.
- 장점과 단점이 모두 비어 있으면 발행하지 않는다.
- "좋습니다", "추천합니다"처럼 일반적인 문장만 있으면 발행하지 않는다.
- 검색 결과 수와 마지막 데이터 갱신일을 관리자 화면에 표시한다.
